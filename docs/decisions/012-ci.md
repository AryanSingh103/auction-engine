# 012. Continuous integration on GitHub Actions

## Context
The brief requires tests running in CI on every push from M1, with `go test -race` clean. The integration tests need a real Postgres.

## Decision
`.github/workflows/ci.yml` runs on push and pull request, with three parallel jobs:
- **lint:** golangci-lint pinned to the same version as local.
- **test:** `make fmt-check vet test-race`. testcontainers uses the runner's Docker, so integration tests run exactly as they do locally.
- **docker:** builds the image.

`permissions: contents: read`, `persist-credentials: false`, per-job timeouts, and superseded runs are cancelled. The first run passed in about 1.5 minutes.

## Alternatives considered
- **A Postgres `services:` container** instead of testcontainers: CI and local would diverge, and the per-test template databases would need rework.
- **Pinning actions by commit SHA:** stronger supply-chain protection, but unreadable and needs Dependabot to maintain. We pin major tags (`@v7`) and accept that trust in the action owners. We'll revisit when deploy secrets arrive (M6).

## Consequences
Every commit shows pass or fail. Actions minutes are free for this public repo. The Makefile targets are the single source of truth for both local runs and CI.
